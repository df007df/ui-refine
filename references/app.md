# App 界面

根据目标子应用、构建配置和发行目标识别 iOS、Android、RN/Flutter 或桌面。App 品牌通过目标平台允许的主题、字体、内容与适当动效表达；现有系统交互、导航、返回和状态必须保持可用。

## 原生 iOS / iPadOS

继续现有 SwiftUI/UIKit/跨平台实现，优先复用项目合适的系统控件和主题角色。safe area、导航层级、真实 TabBar、返回手势、sheet 的完成/取消和焦点是结构的一部分。全屏背景可以延伸，操作与阅读区域要避开系统遮挡。

文字采用适合角色的系统文字样式与缩放策略，检查 Dynamic Type 和中文长文；颜色从现有语义角色/主题生成浅深模式。按项目需求使用系统图标或已确认的品牌图标，避免临时混入不同语法的控件。

检查弹层/键盘遮挡、滚动位置、表单恢复、触控目标与 VoiceOver 标签/顺序。允许用户中断动画和返回，减少动态效果时仍能理解状态变化。大屏采用目标 iPad 的实际布局，不通过缩小整个手机画面证明适配。

## 原生 Android

继续 Compose/Views/跨平台实现及项目 Material/theme；使用已有角色颜色、文字尺度和控件。按窗口实际大小安排导航和列表，处理系统栏、切口、手势和 IME insets，保持系统 Back/返回链。

文字跟随系统字体缩放，浅/深主题分别检查；大屏/横屏保持信息关系和操作可达。TalkBack、键盘、错误反馈和系统减少动画设置随改动检查。平台控件版本/API 行为从项目依赖和当前官方文档核验，不把研究快照的版本标签当成项目要求。

## RN / Flutter

共享产品事实、设计角色和组件职责，按每个发行 OS 检查原生结构与交互。保留现有导航、theme 和状态持有者；按任务提取小组件和编辑状态边界，避免同时引入新的路由/状态框架。

阅读器、列表和输入界面重点检查字体放大、中文换行、safe area、键盘、返回、滚动/阅读位置与主题。跨平台只测一个 OS 不能代表另一个；Web target 的证据单独记录。

## 桌面 App

Electron/Tauri 的 Web shell 复用 [Web](web.md) 的渲染判断；菜单、窗口、平台快捷键、焦点切换和窗口生命周期在实际桌面运行时检查。原生桌面框架按现有系统控件与 API；窗口从最小尺寸到常用尺寸都能完成主要任务。

桌面 hover 之外保留键盘操作和可见焦点，窗口缩放/多栏布局不藏掉主动作。系统主题、文件/剪贴板等能力有改动时验证相应真实入口。

## 重构与实际证据

视图提取围绕明确的职责、值/动作接口和状态所有权。UI 修复不改变业务状态含义、保存方式或已确认的导航/阅读行为。具体迁移见 [重构](refactor.md)。

原生 iOS 的画面来自目标 Simulator/设备，Android 来自 Emulator/设备；构建和截图命令采用当前项目及已选的具体设备，不能无条件操作任意 booted/attached 设备。更改主题/字号等测试设置时记录原值，结束后恢复本轮更改。

| 证据 | 可说明 | 不能自动说明 |
| --- | --- | --- |
| 原生源码/编译 | 静态规范或编译成立 | 真实布局、操作与设备体验 |
| 模拟器/设备截图且已查看 | 对应屏幕、状态、尺寸的画面 | 未执行的交互、手势或性能 |
| 实际操作/录屏 | 已执行流程与动效 | 未测试 OS/设备或发行构建 |
| 浏览器原型/手机仿真 | Web/设计意图 | 原生 App 已运行或真实 App 导航已保留 |

工具名含 `Native` 不等于支持 iOS/Android。Impeccable 的 `NativeComponentCapturer` 使用 Chromium/CDP 截网页，只能作为其实际 Web 能力使用；PNG 差异工具也不会替代原生运行取证。

缺少目标 Simulator/Emulator/设备时，完成可做的源码/构建检查，视觉与原生交互保持 `unrun` 或限定范围的 `partial`，列出需要运行的屏幕和状态。模拟器的手势/性能证据与真机测量分别记录。
