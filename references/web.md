# Web 界面

网站和 Chrome 中的普通网页读取本文件；扩展自身 UI 另读 [Chrome 扩展](chrome-extension.md)。

## 读取现有实现

确认目标路由/页面、构建方式、设计 token、共享组件与真实内容。使用项目实际开发/预览入口，沿已有框架和库修改。给定网址只够评审运行画面；写项目代码需要对应源码，浏览器里的临时 CSS 修改另作诊断记录。

| 页面 | 布局判断 |
| --- | --- |
| 营销/作品集 | 明确价值与主动作，素材和构图表达品牌；长页有节奏，价格/评价等事实可查 |
| 后台/编辑器 | 保留对象、状态、筛选、行列比较和高频操作；任务所需密度明确，层级与反馈优先 |
| 文档/阅读产品 | 实际中文长文、混排、目录、代码/表格、检索与缩放可读 |

## 布局、主题与资源

选择内容需要的容器和断点，检查项目代表性宽度。窄屏重排列、操作和导航；表格在自身区域保持可比较列或采用项目明确的移动展示策略。修复导致横向溢出的声明源，避免全局 `overflow:hidden` 把内容和焦点藏掉。

采用实际字体回退、语义颜色和主题，检查长文本、字体加载及浅/深模式。关键主动作尽早可达；图片尺寸与裁切明确，媒体和重动画的加载/播放按任务安排。优化性能先看实际资源、请求或运行证据，再做相关修复，不把未测的感觉称为提速。

## 操作与可访问性

按钮、链接、字段、表格使用对应语义。键盘可完成主流程；焦点可见，弹层打开/关闭有正确焦点和返回路径，错误/成功反馈可被感知。输入框有常驻标签；hover 之外有触控和键盘反馈。

确认加载、空结果、错误、成功、禁用及长内容中受影响的状态。列表/编辑器保留筛选、选择、阅读/滚动位置和编辑内容，按现有契约处理权限与保存。

## 真实验收

使用当前宿主可用且适用的浏览器工具。查看前后代表性画面：目标页面、相同状态和尺寸，包含改动区及相邻内容；长页检查整体与关键局部。截图必须实际查看，必要时记录完整页面和局部。

执行主要动作和恢复路径，不能仅用 DOM 数量判断设计质量。保存后重读，相关断点检查溢出、换行和控件；键盘/缩放/主题测试随改动选用。浏览器仿真手机是 Web 响应式证据，不证明原生 App 或物理触控性能。

没有浏览器时仍可修改源码并跑相关检查，标记视觉/运行未验收；只交付设计说明或原型时按实际交付物说明。更详细的证据字段见 [证据与交付](evidence.md)。
