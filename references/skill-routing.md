# 按需引用技能与工具

本技能的内置参考构成可执行首版。外部技能只补充当前问题的专门知识或工具，先确定实际可用性再读取，不能仅因为名称类似就全部加载。

## 选择表

| 实际需求 | 候选技能/能力 | 使用条件 |
| --- | --- | --- |
| 专项排版/布局/状态精修、审查与组件提取 | `impeccable` | 可用时选相关 playbook；命令是模型流程，Rust/扩展/live 工具需分别确认安装和支持平台 |
| 设计领域知识或栈建议检索 | `ui-ux-pro-max` / UI UX Pro Max | 能找到实际技能或已授权本地工具；输出作为候选，与项目事实和现有设计规范核对 |
| 营销、作品集、新视觉表达 | `design-taste-frontend` / `taste-skill` | 目标确属该用途；选择合适的一套审美尺度，避免相互冲突的规则叠加 |
| React 原语和可访问组件 | `shadcn-ui` | 项目已采用或任务明确需要；继续当前组件方案，不默认迁移库 |
| WXT 生命周期、消息、storage、注入及性能 | `wxt-browser-extensions` | 当前项目确为 WXT；按具体问题读取相应规则，平台事实以当前官方 API 为准 |
| 跟手、弹簧、可中断与减少动态效果 | `apple-design` | 当前交互需要；区分其 Web 示例与原生 API，使用目标栈实现 |
| Web 实际画面与操作 | 当前宿主浏览器工具；可用的 `ego-browser` / `playwright` 等 | 依宿主与工具适用规则使用；不把浏览器仿真当作原生 App |
| 素材生成或分析 | 可用的图像生成/媒体分析技能与工具 | 素材承担实际内容且任务已授权；先复用真实资产，按所选工具说明执行 |

名称是候选，实际安装可能来自插件并有不同前缀。通过当前技能清单或明确位置查找；本机研究 checkout 不能当作已经安装的技能执行。找到的技能按其访问机制读取，只加载与当前问题相关的部分。

## 冲突和缺失

优先序：用户已确认目标/范围 → 产品和平台约束 → 项目实际规范 → 本技能的任务判断 → 可选审美建议。来自其他技能的硬编码字体、颜色、hero、密度或动画偏好需按当前任务适配。

同一问题有多个候选时，先选最贴合当前载体与已用技术的一个；确有缺口再补充。`design-taste-frontend` 的营销规则不默认成为后台/编辑器/App 的规范。Web、WXT、原生指引不能互相替代真实验收。

外部技能不存在时继续用内置参考和项目资料；关键平台/API 事实不确定时查当前官方文档。缺少可运行工具时记录相应未验收项。安装、自动更新、hooks、远程服务/付费 API 和发布按用户请求及现有授权单独处理，不由“引用技能”推导授权。

专项执行产物写入当前项目任务目录；记录实际选用的技能、范围与重要决定。真实反复出现的缺口再完善本技能对应参考，避免把一次偏好或偶发错误扩成所有任务的规则。
