# 界面代码重构

用于 token、样式、组件、UI 状态和展示结构的整理。范围来自用户要求，不把界面任务扩大为服务/API、数据库或全项目架构迁移。

## 先确定行为与真源

读目标页面、其共享组件/主题以及与改动有关的状态路径。确认输入、输出、事件、路由、权限、状态值、保存时机和错误恢复；保留工作区已有改动。从现有代码确认 token/组件库，不根据风格参考推断项目技术栈。

改动前记录代表性状态和主动作结果。有实际运行条件时留视觉基线；仅有源码时明确范围。已有规范直接引用，冲突先定位实际实现与已确认决定，不新建另一套平行权威。

## 问题到修改位置

| 发现 | 优先修改 | 复查范围 |
| --- | --- | --- |
| 相同角色的色彩/间距/圆角漂移 | 主题角色或共享 token | 已知使用该真源的代表性组件与页面 |
| 相同功能多套控件 | 当前组件库/共享组件及调用点 | 标签、禁用、焦点、布局及旧调用行为 |
| 单页特殊密度或布局 | 局部布局或有意义的 variant | 目标页与受影响尺寸，不全局覆写 |
| 重复 UI 与业务逻辑混在大组件 | 按职责提取展示组件、UI 状态/动作边界 | 原 props/回调、保存顺序和错误恢复 |
| 同一数据多份“真值” | 找出保存真源和暂存编辑状态 | 初次恢复、并发/旧响应、取消/重试 |
| CSS 覆盖层层堆叠 | 找到声明源，整理作用域/选择器 | 同角色状态，宿主/主题与断点差异 |
| 文档和实现不同 | 更新实际改变的决定或实现 | 一份主规范与源码一致 |

先修共享真源，再逐步迁移调用点；兼容现有 variant 和数据契约。组件提取须有复用、职责或理解收益，不能以降低行数作为唯一理由。表格、表单、导航的区别来自任务，不能为了统一外观抹掉行为。

## 栈和状态

- Web：继续项目的 CSS/Tailwind/主题与组件方案。组合展示和动作，保留语义 HTML、焦点、事件和可访问名称。
- SwiftUI/UIKit：让视图与输入/输出边界清晰，主题来自现有环境和语义角色；保留导航、系统返回及阅读/滚动状态。
- Compose/Views：沿用现有状态持有者；合适处提升状态，控件通过值/回调组合，保留 Back 和系统 inset。
- RN/Flutter：复用当前 theme/组件，明确路由与编辑状态归属；列表性能优化要基于实际数据或测量。
- Chrome：恢复状态来自合适的扩展存储/消息边界，组件的短生命周期不承担必须跨生命周期保持的真值。细节见 [Chrome 扩展](chrome-extension.md)。

## 验证迁移

用真实输入/原有检查验证此次受影响的行为：动作仍可达；字段与状态值相同；保存后重新读取；错误后输入/位置仍在；共享组件使用者没有回归。新逻辑或真实缺陷必要时补行为测试；纯视觉小改优先实际渲染与操作检查。

静态检查、构建、单元/集成测试、浏览器/设备运行各证明不同内容，按 [证据与交付](evidence.md) 记录。若关键行为无法运行，交付修改和具体待验收项，不用文件更少或构建成功宣称行为等价。
